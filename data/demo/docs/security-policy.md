# Security Policy

Owner: Devon Lee, Senior Engineer, Identity. This policy covers internal systems and employee practices. It does not cover customer-facing Atlas SSO, which is tracked under the Enterprise SSO (Keystone) project.

## SSO requirements for internal tools

- **Every internal tool must sit behind company SSO.** This includes Slack, Linear, Zendesk, the wiki, GitHub, the finance portal and the HR portal.
- New SaaS tools must support SAML or OIDC before they are approved. Tools without SSO need a written exception from Raj Mehta (CTO).
- Shared accounts are not allowed. If a vendor only offers one login, store it in the team password vault with named access.
- Access is granted by group (for example `group:dept:support`) and is reviewed every quarter by managers.
- Offboarding: SSO access is revoked within 1 hour of a departure.

## Authentication

- MFA is mandatory, with hardware security keys or a platform authenticator. SMS is not allowed.
- Passwords for non-SSO systems: at least 14 characters, generated by the password manager.

## Devices

- Company laptops must have full-disk encryption and auto-lock after 5 minutes.
- Install OS updates within 7 days of release.
- Robot lab laptops connect to the isolated lab network only.

## Data handling

- Customer data (robot telemetry, warehouse layouts, invoices) stays in approved systems.
- Never paste secrets, API keys or customer data into Slack or unapproved AI tools.
- Production database access goes through the bastion with just-in-time approval.

## Firmware and production

- R2 firmware releases must be signed. Signing keys live in the HSM, with access limited to the release owners.
- Production deploys require code review and CI checks to pass.

## Incident reporting

Report suspected phishing, lost devices or data exposure right away in #eng or directly to Devon Lee. Raj Mehta is the escalation point.
